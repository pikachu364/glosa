## 4. 直近の主作業：v2〜v4

JMPlayer の形式資料：
https://github.com/jihodaya/jmplayer/blob/main/docs/formats/sng-ballade.md

v2〜v4 の主な論点は、SNG の版違いだけでなく、**SNG2S と JMPlayer の処理・解釈の違い**にある。同じ挙動だと仮定せず、次の観点で整理する。

1. ファイルの読み取りと版別レイアウト
2. テンポ値の解釈、tempo event の生成、再生時の消費
3. ノート、Tie、step、gate、nudge、tick の扱い
4. conductor の小節数と各パートの終端
5. トラック・チャンネル・イベント順序
6. 不正・欠損・内部整合性のないファイルへの対応

差分は「確認済み」「有力な説明」「未確認」に分ける。SNG2S の MIDI 出力処理と MIMPIV4 の実再生処理は別物として扱い、同じテンポ式を使うと決めつけない。

### テンポスライダー

JMPlayer の形式資料には、SNG2S にテンポ値 1〜127 を与えた測定結果として、次の式が記録されている。

`BPM = 2v - ceil(v / 8)`

例：61 → 114 BPM、72 → 135 BPM、91 → 170 BPM。資料では、3/4 拍子で同じ値から BPM が 1 高くなるのは SNG2S の丸めと説明している。ドライバーのタイマー設定は拍子を参照しない、という分析である。

これは SNG2S の測定・変換挙動として扱う。MIMPIV4 の再生中テンポ計算や Glosa の全バージョンの仕様へ、追加根拠なしに一般化しない。

### 参照と一致しないファイル

JMPlayer の資料では、SNG2S と一致しない2曲について次の説明がある。

- `MAGICAL0.SNG`：126 KB で切れたファイルで、リズムパートが半分欠けている。他の9パートを再生できるよう、末尾ブロックのみ EOF 越えを許す扱い。
- `3X3EYES2.SNG`：SNG2S と合わせるには途中に 10,029 ticks を挿入する必要があるが、ファイルにその指示がない。conductor は97小節、各パートは96小節で内部的に整合する一方、SNG2S の出力は148小節になるため、資料では推測による補正を避けている。

根拠のない時間挿入や長さ補正を通常動作に持ち込まない。ファイル異常・参照処理固有の挙動・Glosa の不具合を区別する。

## 7. v1：現状維持・一時保留

v1 のレイアウト候補は静的解析と fixture の整合に基づく。

- `runner.SNG`：85,897 bytes
- `tableEnd = 114`、legacy `headerEnd = 116`
- part 1 start = 1510
- block size = `entry + 80`
- length fields = `+115 / +117`
- 13 個の相対 seek 値 = `+119..+143`
- note record start = `+145`
- このモデルで runner の Note-on 3,295 件、Note-off 3,295 件を参照と照合した記録がある

`SngConverter.cs` には `ReadLegacyV1Tempi()` がある。公開テスト `BalladeV1RunnerProducesReferenceTempoEvents()` は参照値 500000 / 869000 / 869565 µs/qn の byte sequence を検査し、`BalladeV1KeepsDefaultTempoWhenTempoStreamIsUnchanged()` は変化しない tempo stream の既定値維持を検査する。これらは特定 fixture と検査範囲の結果であり、v1 全体の完全互換を意味しない。

v1 の参照 `runner.MID` は tick 0 = 500,000、tick 8 = 869,000、tick 192 = 869,565 µs/qn。SNG2S の静的解析では raw tempo 37 と base tempo 120 から 69 BPM、整数演算経路から 869000 と 869565 が得られる。一方、tick 8 にイベントが出るまでの pending-delta / absolute-tick の因果関係、`0x6EE` の初期値、setup SysEx producer と payload の対応、参照 MIDI の実際の SNG2S オプションは未確定。

詳細は [V1_TEMPO_INVESTIGATION.md](V1_TEMPO_INVESTIGATION.md) と [NEXT_STEPS.md](NEXT_STEPS.md) の T-017 を参照する。未解決点を理由に、既存実装や回帰テストを推測で変更しない。v2〜v4 の調査が落ち着いた後に再開する。

## 8. MIMPIV4 再生テンポ

静的解析で確認された timer 初期化・割り込み関連の経路：
- `FUN_1FF5_1344`：driver dispatch
- 選択された setup 分岐で `0x0438 → 0x0440` のコピー
- `FUN_1FF5_0D61`：INT 8 handler 設定
- `FUN_1FF5_0DFA`：timer divisor 計算と I/O port 書き込み

SNG tempo record の第2 word が再生中に `0x0438`、`0x0440`、`0x7BF0` を更新する経路は未確認。再調査時は初期化経路を繰り返すのではなく、再生レコードの parser/caller と再生中の global 書き込みを追跡する。静的データだけでは確定できない場合は、その制約を記録し runtime trace が必要と明示する。
