## 確認済みの事実（直前の調査報告に基づく）

1. `FUN_1000_22FC` は MIMPIV4 の **mode-1 読み込み処理**として特定された。
2. この処理はトラックデータ用領域を確保して読み込み、ヘッダー情報から `0x0440` の初期値を設定する。
3. mode-1 のドライバー選択時、`FUN_1FF5_1344` は `1FF5:1430` を間接呼び出し先に設定し、`FUN_1FF5_1409` がその呼び出しを実行する。
4. 現在取得できている Ghidra 出力には、`1FF5:1430` の関数本体・命令列が含まれていない。
5. 現段階では、読み込んだトラック内のテンポレコードを再生時に消費する関数は特定できていない。

上記は静的解析・解析データに基づく調査結果であり、実行時トレースや実再生で確認済みという意味ではない。

## 未確定事項・注意点

- `1FF5:1430` がテンポレコードの消費処理を行うかどうかは **未確定**。有力候補としても断定せず、まず関数本体を取得して命令列・参照元・参照先を調べる。
- mode-1 の証拠を mode-2 の処理や `/Zbar` のタイマー経路と混同しない。
- 読み込み時に `0x0440` を設定することだけでは、再生時のテンポ更新方式は説明できない。
- 解析データが欠けていることは、対象関数が存在しないことを意味しない。
- 変換器の修正を先行させない。内部動作の推測だけでオフセットやテンポ処理を変更しない。

## 安全な GitHub 作業方針

- main へ直接変更を加えず、文書変更も原則としてブランチと PR で提案する。
- 安全性チェックや CI で問題が出た場合は、マージせず PR 上で原因を調べる。チェックが通った場合でも、ユーザーの意図や既存 PR の状態を確認せず自動的にマージしない。
- 既存の PR #52 を確認せず、同じ内容を重複して main に追加しない。
- 非公開の Ghidra データ、元 EXE、個人環境由来の解析資料を公開リポジトリにコピーしない。公開してよい根拠を確認できない解析データは、パスや内容を含めて公開しない。
- 事実・推測・未解決事項を明示する。未確認の内容を「確認済み」と書かない。
- コード変更が必要になった場合は、変更前に対象、根拠、テスト計画を整理し、最小限の差分で検証する。
