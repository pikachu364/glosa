## Findings from SNG2S.DOC (version 3.3)

The documentation describes SNG2S as a converter for Music-kun, Music Rou, and Ballade SNG data to Standard MIDI Files. It states that version 3.0 added Ballade 3 support. It also says reverb, master volume, and other SysEx data are converted, and that Ballade/Ballade 2 user tones can be converted.

Documented options relevant to comparisons:

- `/0` and `/1`: create MIDI Format 0 or Format 1; Format 1 is the default.
- `/F`: order output MIDI tracks in ascending SNG track order. Without it, output track ordering is reversed according to the documented Ballade generation.
- `/N`: omit tracks without note data. By default, even unused parts' initial program changes and other events are converted.
- `/MT`: suppress SysEx messages that turn off sound modules not used by a part.
- `/X1`: put SysEx in the conductor track; `/X2` is the default and creates a dedicated SysEx track after the conductor track; `/XD` disables SysEx conversion.
- `/U`: for supported non-Ballade-3 files, map PCM parts to MIDI channels 11–16 without the channel-change SysEx. The documentation says this option is ineffective for Ballade 3.
- `/LA`: map PCM tones to similar MT-32 tones and omit PCM-selection SysEx.
- `/R`: disable running-status rules, producing a larger file for older software that cannot handle running status.
- `/DEF`: create a MIMPI sound-definition file.
- `/O<path>`: select the output directory.

The document says the MIDI timebase is fixed at 48 ticks per quarter note. It warns that output MIDI files are overwritten if they already exist, and that `/DEF` similarly overwrites an existing DEF file. It also states that Ballade 2 PCM user tones are not supported by this version.

The docs explain that module-off SysEx can silence playback on a different sound module; `/MT` suppresses those messages, but does not by itself resolve different tone numbering. Therefore, a comparison should separately inspect SysEx events, program changes, channel assignments, track order, and timing.

## Findings from README.DOC

The version 3.3 readme says:

- Version 3.0 added Ballade 3 support.
- From version 2.0 onward, song titles and track names are emitted as MIDI meta event `FF 03` (Track Name), rather than `FF 01` (Text Event).
- Version 3.3 fixed a bug in version 3.2 where Ballade 3 tracks 11 and above were not converted when `/N` was used.
- Versions 3.0–3.1 are explicitly described by the author as producing incorrect conversions; the readme advises against using them.
- Version 3.3 includes optimizations that slightly reduced executable size.

These release notes make version verification important. The local files are named and documented as version 3.3, but the binary version should be confirmed if a reliable non-destructive method is available. The `FF 03` versus `FF 01` distinction is also a useful specific check when inspecting MIDI metadata.

## Investigation plan

1. Parse `runner.MID` without playing audio. Record MIDI format, track count, division, tempo, event counts, note ranges, controllers, program changes, SysEx events, meta events, and end-of-track timing.
2. Check track-name/title metadata for `FF 03` events and note any `FF 01` events.
3. Compare those results with a MIDI generated by Jmplayer from the same SNG input, if available.
4. Identify concrete event-level differences before drawing conclusions about the converter.
5. Keep tests read-only and do not overwrite source files.
